# 任意门转发与节点绑定

任意门是 **TCP/UDP 入口转发**。例如入口 A 转到 Shadowsocks 目标 B：入口运行任意门，但客户端仍使用目标 B 的 Shadowsocks 协议与凭据。

[![任意门入口与目标节点及协议继承关系](/images/forwarding.svg)](/images/forwarding.svg)

## 为什么看见 DD 又看见 SS

DD/任意门描述入口机制；SS 描述客户端协议。两者可以同时成立。当前 UI 把转发入口作为目标节点的关联条目显示，编辑器区分入口类型和继承的客户端配置，避免混淆。

[![实际界面：转发入口紧随绑定目标显示，演示数据](/images/node-group.png)](/images/node-group.png)

*截图来自当前前端构建与隔离演示数据。目标和入口为绑定关系，名称相似本身不会建立绑定。点击图片可在原图中查看细节。*

## 创建前准备

| 准备项 | 检查点 |
| --- | --- |
| 目标节点 B | 已启用的受管物理代理节点；入站与客户端配置正常 |
| 入口服务器 A | Agent 在线、有可用端口、可访问 B |
| 网络 | A → B 的目标端口 TCP/UDP 按需可达 |
| 授权 | 当前操作者有权管理相关资源；用户端按授权获得个人配置 |

当前目标选择不接受自身、其他转发入口、路由条目、纯导入条目及不兼容类型。不能通过嵌套选择制造环路；要构建多跳应使用对应转发功能。

## 编辑与切换目标

打开转发条目编辑器：

1. **节点名称**用于展示。
2. **节点类型**显示任意门 TCP+UDP。
3. **转发目标**从已有节点选择；更换后核对目标名称、协议与凭据继承预览。
4. **转发地址**选择服务器 IP 或域名，新选目标默认使用服务器 IP。
5. 保持入口服务器与监听端口正确，保存并等待远端确认。

[![实际界面：选择目标并使用其服务器节点域名](/images/forward-editor.png)](/images/forward-editor.png)

*图中“目标域名”来自目标服务器管理，已有域名时只读；这里不是入口的客户端分享域名。*

保存涉及实际入站目标、继承的订阅配置和持久化绑定。成功后入口应显示在**新目标下面**，重开编辑器也应保持新绑定。

## IP 与域名怎么选

| 模式 | 适用 | 特点 |
| --- | --- | --- |
| 服务器 IP | 地址固定或暂未使用域名 | 转发意图中使用地址，需留意动态 IP 变化 |
| 域名 | DDNS、动态 IP 或希望固定名称 | 保存域名字符串，由运行时解析；受 DNS 缓存及连接复用影响 |

域名模式优先显示目标服务器的**节点域名**。已配置时到服务器管理修改；未配置时可以输入，界面提示保存后同步到服务器管理。详情见[动态 IP 与域名](/docs/nodes/domains)。

## 保存失败、冲突或超时

- 远端拒绝：保留错误，修复端口、目标或核心配置后重试。
- 旧页面冲突：刷新获取最新绑定再提交，避免覆盖其他管理员修改。
- 等待确认超时：检查 Agent、实际监听与当前绑定，不把请求发出当成成功。
- 目标已有其他入口依赖：按界面提示先解除下游关系，再调整类型或绑定。

对远端状态不确定的操作，系统会尝试补偿并报告结果；不要为了消除提示直接改数据库或重复点击。

## 完整验收

1. 列表分组和重开编辑器的绑定一致。
2. 入口核心中的转发地址/端口正确。
3. 客户端配置保留入口地址/端口，协议和个人凭据继承目标。
4. 从客户端经入口完成真实访问，TCP/UDP 分别按需求测试。

若只有列表变了但业务仍走旧目标，检查远端是否确认、客户端是否刷新配置，以及旧连接是否仍在使用。
