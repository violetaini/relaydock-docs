# 动态 IP、节点域名与地址选择

同一台服务器可能同时有“检测到的公网 IP”“管理地址”“节点域名”和“TLS SNI”。设置域名前先看[字段对照](/docs/servers/server-fields)。

[![域名在直连、转发和二维码中的取值关系](/images/domain-flow.svg)](/images/domain-flow.svg)

## 一：给动态 IP 目标配置域名

示例：目标 B 的公网地址会变化，希望入口 A 始终转发到 `origin.example.com`。

1. 在 B 的服务器管理中填写**节点域名** `origin.example.com`。
2. 用本面板受支持的 DDNS 或已有外部 DDNS 更新 A/AAAA。
3. 从入口 A 的网络解析该域名，确认指向 B 的当前可达地址。
4. 编辑任意门入口，选择 B，再把转发地址切换为域名。
5. 核对显示的目标域名，保存并等待远端确认。

仅把 IP 修改成域名不会自动创建 DNS 记录，也不会自动签发证书。

## 二：服务器还没有节点域名

任意门编辑器允许在域名模式输入有效主机名，并提示**将同步到服务器管理**。保存时同时处理目标绑定、域名和相关配置；远端拒绝时不应假装所有设置均已生效。

已有节点域名时输入框只读。统一在服务器管理维护，避免每个入口保存不同且难以追踪的值。

## 三：生成的客户端链接用哪个域名

| 分享对象 | 使用的地址 |
| --- | --- |
| 普通受管节点 | 对应服务器的最新节点域名，未设置时按当前节点地址 |
| 任意门入口 | **入口服务器 A** 的节点域名及入口端口 |
| 转发的远端目标 | 核心侧使用 B 的目标地址，客户端不直接跳过 A |
| 已明确选择的中转/路由/特定 IPv6 入口 | 保留其专用路径，不无条件覆盖 |
| 外部导入节点 | 不因名称相似被绑定到任意本地服务器 |

分享生成会保留当前用户凭据，不应因为替换地址而换成管理员或其他用户的凭据。

## 修改已有服务器域名之后

重新生成分享链接和二维码会读取最新服务器节点域名；客户端此前保存的静态 URI 不会自动改写，应刷新订阅或重新导入。

已有任意门的实际目标不保证在改服务器字段后无条件立即批量重写。重新打开转发编辑器，核对最新域名并保存，使远端目标与预期一致。

## DNS 变化为什么不是立刻生效

从 IP 变化到真正改走新地址，可能经过：

```text
公网 IP 探测 → Agent 上报 → DNS 写入 → 递归缓存过期 → 核心解析 → 新连接建立
```

TTL、操作系统/核心缓存和仍在使用的连接都会影响时间。先检查各阶段，不要频繁重启全部服务。

## 验证命令

```bash
dig +short A origin.example.com
dig +short AAAA origin.example.com
```

应在客户端、控制端和转发入口分别查询，避免只检查自己电脑。没有可用 IPv6 时，错误 AAAA 会造成部分客户端优先连接失败；DDNS 某次未收到 IPv6 不等于会自动删除旧记录。
