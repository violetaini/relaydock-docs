# 创建、编辑与验证节点

先区分“核心上的入站”和“客户端节点条目”。受管入站可以同步出客户端节点；导入一条 `ss://` 等链接，只是保存连接配置，不会自动在远端创建监听。

## 选择创建路径

| 需要什么 | 操作位置 / 路径 |
| --- | --- |
| 在自己的服务器创建服务 | 服务管理 → 服务器操作 → 入站管理 |
| 管理已有客户端条目 | 节点管理 → 编辑/导入 |
| 为目标节点增加入口 | 对受管节点创建转发，再维护[绑定关系](/docs/nodes/forwarding) |
| 用户自助开通 | 先配置[服务授权](/docs/users/authorization)，再由用户门户开通 |

## 创建受管入站

1. 确认 Agent 在线、核心模式正确。
2. 选择当前界面提供的协议组合，填写唯一 tag、监听端口及必要参数。
3. 对 TLS 组合选择匹配域名的证书；对 REALITY、WireGuard 等填写对应专用字段。
4. 保存并等待远端执行结果。
5. 查看入站列表与节点管理，确认同步条目的服务器、端口和协议。

协议支持依赖**核心类型、版本、客户端和所选组合**。不要把导入解析器支持某种格式，误认为任意核心都能创建这种服务。

## 常用参数怎么理解

| 参数 | 说明 |
| --- | --- |
| 名称 | 展示用途，不决定实际流量路径 |
| tag | 核心对象标识，路由与同步可能引用，别随意重复 |
| 监听地址 | `0.0.0.0` 对外监听；`127.0.0.1` 仅本机，需匹配前置拓扑 |
| 端口 | 核心监听端口，需同时检查 TCP/UDP、防火墙及安全组 |
| UUID / 密码 / 密钥 | 协议凭据，管理端与用户端要正确匹配 |
| SNI / Host / path | TLS 和传输参数，不能只改地址不核对这些字段 |
| 节点域名 | 来自服务器管理，可影响分享地址，详见[域名规则](/docs/nodes/domains) |

## 编辑时的同步边界

受管节点基础字段可能回写完整客户端配置。复杂配置修改前导出备份，核对 YAML/JSON 中地址、端口、协议、TLS 和传输参数是否一致。

任意门入口使用专用编辑器：目标从已有受管节点选择，不把入口伪装成可随意切换协议的独立普通节点。见[任意门绑定](/docs/nodes/forwarding)。

## 验证一条节点

- 远端核心没有配置错误且端口由预期进程监听；
- 从客户端网络能连接业务端口；
- 导入配置与当前服务器及用户凭据一致；
- 客户端实际建立连接并访问测试目标；
- 对应用户/节点流量能按预期归因。

如果节点显示但处于凭据待开通状态，应等待或检查用户凭据部署，不能临时分发所有者凭据“解决”。

## 删除前检查

检查是否被套餐、固定节点授权、转发入口、订阅或路由引用。删除远端入站、删除客户端条目和停用用户是不同操作；确认影响范围后执行，避免留下指向不存在目标的转发。
