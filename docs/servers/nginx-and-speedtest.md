# Nginx 管理与测速

Nginx 前置、面板 HTTPS 与代理核心是相互关联但独立的组件。调整前先确认 80/443 当前由哪个进程监听。

## Nginx 两种管理方式

| 模式 | 谁维护配置 | 推荐场景 |
| --- | --- | --- |
| 托管 Nginx | RelayDock 对受管配置执行管理 | 新服务器、没有其他站点 |
| 复用现有 Nginx | 保留系统/其他面板的安装与管理关系 | 宝塔、1Panel、已有网站 |

复用不等于可以覆盖已有站点。确认配置目录、include 关系、证书位置及重载命令。托管前应备份原文件和服务状态。

```bash
sudo ss -lntup
sudo nginx -t
```

先测试配置再重载，失败时保留首个错误及具体文件行号。

## 面板测速与客户端延迟

测速存在不同观察位置：

| 测试 | 测量的链路 | 不能证明什么 |
| --- | --- | --- |
| 主控 Ookla 测速 | 控制端到测速服务 | 不代表远端节点速度 |
| 远程服务器 Ookla 测速 | 节点主机到测速服务 | 不代表用户经过整条代理链的速度 |
| 客户端/代理实测延迟 | 客户端经过所选连接到测试目标 | 不等同于持续吞吐能力 |
| 独立测速端 | 测速端所在网络发起的测试 | 不能代表所有运营商与地区 |

## 服务器测速操作

在服务管理打开目标服务器操作窗口，进入测速相关入口，按提示安装/调用受支持测速组件。先确认选中的机器名称，再运行测试。

测试会消耗真实流量和带宽；有小额流量套餐、按量出站计费或生产业务时，选择低峰并记录测试时间。测试成功后保存结果和测试目标，比较时保持条件一致。

## 故障处理

- 安装失败：看下载地址、架构、执行权限和目标磁盘。
- Ookla 无结果：确认可访问测速服务、运行许可提示及网络策略。
- 面板速度高但客户端低：检查入口、出口、运营商路由、协议开销和限速策略。
- 端口 443 启动失败：检查已有 Nginx、核心、其他面板及容器占用，不要直接结束未知进程。

前置伪装的域名和端口拓扑见[前置与伪装](/docs/features/camouflage)。
