# 服务器字段与动态公网 IP

入口为 **服务管理 → 添加/编辑服务器**。有些页面或旧版叫“服务器管理”。域名相关字段用途不同，应先按下面的表确定要改哪一个。

## 地址字段对照

| 字段 | 用途 | 示例 |
| --- | --- | --- |
| 公网 IPv4 / 初始地址 | 记录当前公网地址，可由 Agent 上报更新 | `192.0.2.20` |
| 服务器地址 / DDNS 域名 | 控制连接等管理用途；显式域名不会被普通 IP 更新覆盖 | `manage.example.com` |
| Agent 监听端口 / Pull 端口 | 对应所选控制模式的端口 | 以生成命令为准 |
| 节点域名 | 客户端连接地址、域名转发和相关域名配置的依据 | `origin.example.com` |
| TLS SNI / Host | 对应具体入站的 TLS/HTTP 参数 | 根据协议组合配置 |

域名字段填主机名，不填 `https://`、路径或 `:端口`。端口在独立字段填写。

## 动态 IP 会自己更新吗

当前 Agent 会定期探测公网地址并上报，常规检查约为分钟级，失败重试与网络情况会影响时间。控制端根据认证/心跳等更新服务器地址数据及相关节点信息。

- 探测暂时失败不应把已知地址直接清空。
- 管理地址为空或跟随旧 IP 的场景可以随 IP 变化更新；显式填写的域名会被保留。
- “数据库已更新 IP”不代表 DNS 已更新，还需要配置 DDNS 或外部 DDNS。
- 多网卡、NAT、隧道出口或策略路由可能让探测地址与真正对外入口不同，需要人工验证。

::: tip 推荐做法
动态 IP 服务器使用固定域名作为客户端入口，让 DDNS 更新解析。这样客户端不必因每次 IP 变化重新获取写死 IP 的链接。
:::

## 节点域名的影响范围

1. 当前分享链接与二维码会优先读取对应服务器的节点域名。
2. 任意门选择域名模式时读取**目标服务器**节点域名。
3. 转发入口的客户端分享链接使用**入口服务器**节点域名。
4. 已生成到客户端本地的静态链接不会被远程修改，必要时刷新订阅。

已有任意门目标并非在修改服务器域名后无条件全部立即重写。打开转发编辑器会读取最新域名，确认后保存以应用，见[域名转发](/docs/nodes/domains)。

## 其他常用设置

| 设置 | 作用 / 注意事项 |
| --- | --- |
| Xray 模式 | 内嵌或外部；切换前处理端口和原核心归属 |
| Nginx 模式 | 托管或复用；不要同时修改同一份站点配置 |
| 流量来源 | 系统网卡或 Xray 聚合，只改变服务器层口径 |
| 统计方向 | 双向、取大、仅上行或仅下行，以当前界面为准 |
| 每月重置日 | `0` 不自动重置；与用户套餐周期不同 |
| IPv6 | 只在真实可达且需要的情况下启用/发布 |
| DDNS | 需可写域名的凭据与受支持服务商 |

## 修改后怎么验收

保存后重新打开编辑器，确认持久化值；查看 Agent 心跳、DNS 解析、分享链接和实际业务连接。更换 IP/域名可能同时影响反代、证书及外部监控，需要按真实使用路径逐项核对。
