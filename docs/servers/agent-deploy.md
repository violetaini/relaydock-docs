# Agent 安装、接入与守护

Agent 安装在**承载节点的服务器**上，用于上报状态和执行核心管理。它与控制端是两个组件，安装面板不会自动接管所有机器。

## 1. 创建服务器记录

进入 **服务管理 → 添加服务器**，设置名称和连接模式。新环境优先使用 WebSocket；已有服务环境先选好[核心模式](/docs/servers/xray-modes)，核对监听端口、Nginx 归属及是否允许接管。

公网 IPv4 可以留空等待 Agent 上报；如果为 NAT、端口映射或指定管理地址场景，需按实际可达地址配置，不能只依赖探测结果。

## 2. 生成并运行本实例接入命令

在服务管理复制面板生成的命令，确认控制端 HTTPS 地址和连接模式。到目标服务器终端执行，保存安装输出。

::: warning 接入命令包含秘密
服务器/Agent 令牌与该实例和服务器记录绑定。不要把完整命令贴入公开 issue、截图或文档；泄露后应在后台轮换相应令牌并重新核对接入。
:::

如果后台提供不同安装选项，应先确定：

| 选项 | 选择依据 |
| --- | --- |
| WebSocket / Push / Pull | 哪一方能主动连接另一方，详见[模式](/docs/servers/connection-modes) |
| 内嵌 / 外部核心 | 新机全托管或接管已有核心 |
| Agent 管理端口 | 仅在实际模式需要时开放，并限制来源 |
| Nginx 模式 | 新安装托管或复用已有 Nginx |

不要为了让安装完成而忽略端口冲突、校验失败或缺少资产的错误。

## 3. 确认连接成功

回到面板，检查在线状态、心跳时间、版本、主机信息及公网地址。再打开服务器操作窗口读取核心和系统状态。

确认“在线”后新建一条受管入站，再验证核心接受配置、监听端口和客户端实测。不要以机器探针有数据代替代理验证。

## 4. 查日志与系统服务

不同代际安装的服务名可能含 `arcway` 或 `relaydock`。先发现实际单元，再查对应日志：

```bash
systemctl list-unit-files | grep -Ei 'arcway|relaydock|xray'
ss -lntup
```

```bash
# 替换为上一步查到的 Agent 单元名
sudo systemctl status YOUR_AGENT_SERVICE --no-pager
sudo journalctl -u YOUR_AGENT_SERVICE -n 100 --no-pager
```

内嵌核心由 Agent 进程运行，代理端口的持有者可能就是 Agent；外部核心则需要核对独立核心服务。

## 在线升级

面板读取到可用版本后可以触发 Agent 升级。先选一台非关键节点测试，再逐批更新。目标服务器需要下载对应架构的 Release 资产。

升级失败应保留**完整下载地址和首个错误**，判断是网络、404/缺资产、架构不符、校验失败、权限或重启失败。`exit status 1` 只是汇总结果。不要反复批量重试掩盖每台机器的根因，见[更新排错](/docs/operations/update#agent-升级失败怎么查)。

## 重装与令牌轮换

重装前确认原安装目录、运行模式及现有入站是否需要保留。不要删除服务器记录来解决单纯的 Agent 离线，因为它还关联授权、节点和统计。

轮换令牌后，旧 Agent 可能需要重新配置。仅替换面板记录、不更新节点侧，通常会导致持续认证失败。
