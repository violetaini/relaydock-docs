# Xray 内嵌与外部模式

两种模式决定由谁运行与维护核心。请在接入服务器时确定，已有业务机器尤其需要避免重复启动。

## 模式比较

| 项目 | 内嵌模式 embedded | 外部模式 external |
| --- | --- | --- |
| 进程 | 核心随 Agent 进程运行 | 独立核心进程/服务 |
| 更新来源 | Agent 所含核心版本 | 对应外部核心的安装/更新流程 |
| 配置与启停 | 由 Agent 执行管理 | 需要正确的路径和服务配置 |
| 适合 | 新机、统一托管 | 已有核心、明确需要独立维护 |
| 排错重点 | Agent 日志、实际监听、配置拒绝 | 额外核对核心路径、权限和系统服务 |

内嵌减少了组件数量，但仍可能与其他进程争抢端口，不存在“内嵌就绝无端口冲突”的保证。

## 新服务器推荐步骤

选择内嵌模式，接入后读取核心状态，创建一个入站，检查实际监听和日志，再测试客户端。无需为了匹配某篇旧教程额外安装第二份 `xray.service`。

## 接管已有核心

1. 导出原配置，备份服务单元、证书和运行参数。
2. 检查核心版本及协议支持，记录现有监听端口。
3. 确认面板配置同步是否会覆盖原来的入站、出站及路由。
4. 选择外部模式并核对执行路径/权限。
5. 在维护窗口执行一次配置读取与最小修改，保留回退路径。

不要让两个管理系统同时写同一个核心配置。面板字段能保存不代表外部核心版本支持相应特性。

## 切换模式的边界

切换模式可能需要停止旧进程、迁移配置并重启，现有连接可能中断。不要宣传为所有配置都无损热切换。

保存前检查端口是否仍被旧进程占用；切换后核对入站 tag、用户凭据、证书路径、统计 API 和防火墙。

## 常见判断错误

- `systemctl status xray` 显示不存在：内嵌模式可能完全正常，应查 Agent 和端口。
- Agent 在线但节点失败：查核心配置错误、端口与凭据。
- 手工改配置又被恢复：可能被面板下一次同步覆盖，应该从受管入口修改。
- 更新 Agent 后协议异常：比较其内含核心版本与客户端支持，不要只比较 Agent 版本号。

节点协议选择见[创建节点](/docs/nodes/create)，日志定位见[分层排错](/docs/operations/troubleshooting)。
