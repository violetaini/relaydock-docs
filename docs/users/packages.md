# 套餐、有效期与限制

套餐用于把固定节点、服务器和转发服务组合成可重复分配的政策。先用一个测试用户验证套餐，再批量分配。

## 配置前先确定四件事

| 问题 | 例子 |
| --- | --- |
| 可以使用什么 | 固定节点、可自助开通的服务器/协议、转发服务 |
| 可以用多久 | 生效时间、到期时间、续期方式 |
| 可以用多少 | 流量额度、周期与统计方向 |
| 可以多快/多少连接 | 速率及连接/设备类限制，依协议能力 |

额度是总量，限速是速率，连接数不是物理设备数。不要用同一个数值同时解释三类限制。

## 创建与分配

1. 在 **套餐管理** 新建套餐，填写名称及服务组合。
2. 配置流量与有效期政策，核对界面单位。
3. 在用户 **服务授权** 中选择套餐模式并分配套餐。
4. 查看分配结果及警告，等待必要的远端部署。
5. 用用户身份测试自助开通、订阅与限制表现。

对某种协议是否能自助创建、能否独立分配凭据，应以界面可用组合和后端校验为准。不要推断所有导入协议都支持相同的多用户模型。

## 继承和覆盖

部分用户限制允许覆盖套餐值，留空通常表示继承；`0` 的含义依具体字段是不限或禁用，应看字段提示，不能全局类推。

固定节点限制、服务器自助服务限制和转发限制分别维护。修改一个层级不会自动把其他层的额度都重写。

## 续期与流量重置

用户设置中的“续期套餐”用于延长有效期，不能默认理解为流量清零。重置功能、重置日和周期设置应独立确认。

服务器每月重置、套餐周期、用户固定节点周期是不同范围。修改服务器统计来源不会改变用户的计费方式。详见[流量统计](/docs/features/traffic)。

## 到期与超额验证

建议在测试用户上设置短有效期或小额度，观察界面状态、后台限制执行及远端实际连接。不要在正式用户上反复重置制造测试数据。

限制依赖采集周期和执行组件，不能保证精确到最后一个字节或零延迟中断；也不能用面板限额替代云厂商出站账单保护。

## 修改已有套餐

先确认会影响哪些用户与服务，备份配置，分批应用。出现部分失败时记录各用户结果；不要直接恢复整份旧数据库覆盖已经产生的新业务数据。
