# 用户、账号状态与服务授权

RelayDock 的用户授权决定谁能使用哪些节点、服务器或转发服务。**外部 SSO 身份验证**与**面板内部服务授权**是两个步骤，SSO 登录成功不会自动赋予全部管理权限。

[![从账号到服务及个人凭据的授权流程](/images/authorization.svg)](/images/authorization.svg)

## 创建用户

进入 **用户管理 → 新建用户**。填写用户名、显示名称、邮箱及初始密码；密码留空时后台可生成随机密码，创建结果只展示一次时应及时安全交付。

不要多人共用管理员账号。邮箱登录依赖唯一匹配；相同邮箱关联多个账号时应优先用用户名并修正资料，不能随机选择一个账号。

## 账号状态与服务状态

| 状态 | 影响 |
| --- | --- |
| 账号停用 | 拒绝该账号继续正常登录/使用受保护资源 |
| 套餐或授权到期 | 账号可能仍可查看门户，但对应服务不可继续使用 |
| 额度用完 | 对应限制触发，不代表密码不正确 |
| Agent 离线 | 影响远端配置执行，不等于账号被停用 |

当前密码正确但账号停用时，登录显示明确停用提示；错误密码仍返回通用凭据错误，避免任意错误请求就能探测账号状态。见[登录安全](/docs/security/login)。

[![实际界面：用户设置中的服务授权、限制与订阅入口，演示数据](/images/user-settings.png)](/images/user-settings.png)

*账号启用、服务授权、限制与订阅是分开的操作；先确定授权方式，再配置可用服务。*

## 两种授权模式

在用户设置的 **服务授权** 中选择：

| 方式 | 用途 | 维护方式 |
| --- | --- | --- |
| 套餐授权 | 多个用户使用同一组服务政策 | 在套餐配置中组合服务，再分配给用户 |
| 自定义授权 | 少量用户需要独立服务范围和限制 | 分别维护该用户的固定节点、服务器和转发授权 |

两种模式互斥，不应把自定义授权与套餐规则简单叠加理解。切换前看清覆盖、迁移或警告信息，完成后重新检查实际可用列表。

## 三类服务的区别

- **固定节点授权**：给用户使用已有节点的权利，限制在对应节点层维护。
- **服务器授权**：允许用户在指定服务器和协议组合范围内自助创建/开通节点。
- **转发授权**：允许使用指定转发模板、路径或资源范围。

可以创建节点不意味着可以操作整台服务器，也不意味着拥有其他用户的凭据。

## 建议操作顺序

1. 创建一名测试用户。
2. 明确选择套餐或自定义模式。
3. 配置服务范围、有效期、流量/速率/连接等限制。
4. 保存并检查逐项执行结果，区分已应用、失败与回滚失败。
5. 使用测试用户登录，确认列表、开通结果和订阅范围。
6. 验证未授权资源不可访问，再扩展到其他用户。

批量授权有部分失败时，不要将总提示当作每个用户都成功。按返回的用户级结果补救。

## 用户凭据与待开通

受管节点可能需要为用户部署个人凭据。条目显示“待开通/待部署”时，检查 Agent 和部署任务。管理员/节点所有者凭据不应作为兜底下发给普通用户。

## 撤销与离职处理

先停用或撤销相应服务，再确认远端凭据和订阅访问的处理结果。已经导出到客户端的静态文件不会自行消失，需要结合凭据撤销、订阅轮换及远端实际状态完成验收。
