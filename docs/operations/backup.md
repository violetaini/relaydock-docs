# 备份、恢复与迁移

备份要能恢复，而不仅是文件存在。更新、迁移、接管旧服务和批量修改前，先取得当前可用备份并记录版本。

## 面板加密备份

在维护/数据备份入口输入备份口令及确认口令，下载加密备份。当前界面要求口令至少 8 位，建议使用更长的唯一口令；口令不会替你保存。

备份包含运行数据和订阅等内容，可能含账号、节点凭据及密钥，需私密保存。备份文件与口令分开存放，不放进文档站、公开仓库或可直接下载的 Web 目录。

## 面板恢复的两个阶段

1. 选择备份并填写原口令，执行**校验并暂存**。
2. 按界面提示在维护窗口重启服务，启动时再应用暂存数据。

“已暂存”不等于运行中数据库已替换。恢复前另外保存当前数据，恢复后核对用户、节点、授权、订阅和版本。

当前界面接受新版 `.zip.enc` 及旧版 `.zip`，并有限制文件大小。以页面校验为准；不要通过改文件扩展名绕过格式错误。

## 人工备份的范围

| 内容 | 为什么要保存 |
| --- | --- |
| 数据库与订阅目录 | 账号、授权、节点和配置 |
| 实际服务配置、环境文件 | 端口、数据库路径、外置前端与部署参数 |
| 证书及私钥、相关外部文件 | 可能不全部包含在同一备份范围 |
| Nginx / systemd / Compose 配置 | 恢复服务入口与托管关系 |
| 当前程序/镜像版本与发布信息 | 确定兼容恢复版本 |

不同部署路径不同，先检查当前服务单元和配置，不要把示例路径当作实际路径。

## 安全复制 SQLite

运行中的 SQLite 可能使用 WAL，单独复制 `.db` 可能不一致。采用应用提供的备份、SQLite 备份接口，或在维护窗口停止写入后复制**实际完整数据目录**。

以下仅示范默认裸机布局，实际服务名和目录确认后再运行：

```bash
sudo install -d -m 700 /root/relaydock-backups
sudo systemctl stop arcway
sudo cp -a /etc/arcway /root/relaydock-backups/arcway-before-maintenance
sudo systemctl start arcway
```

生产环境使用带时间的唯一目录，复制失败也要及时恢复服务；离线备份随后加密并保存到独立位置。

## 迁移到新服务器

1. 记录原版本、架构、域名、端口、Agent 连接方式及数据路径。
2. 准备匹配版本的新环境，保留旧机供回退。
3. 在可控停写窗口做最终备份，恢复到新机。
4. 配置反代、证书和必要外部文件。
5. 从测试入口验证管理员、用户、节点、订阅及 Agent。
6. 再切换 DNS，观察心跳和业务，确认没有双主同时写入。

## 恢复与程序回退的区别

只恢复旧二进制/旧网页，不会回退数据库写入；恢复旧数据库则可能丢失备份之后的新账号、流量与授权。遇到前端错误优先回退相应发布，不要未经评估用整库恢复解决局部问题。

定期在隔离环境进行恢复演练，记录可恢复到什么时间点及缺少哪些外部文件。
