# 登录、双因素认证与账号停用

登录安全由正确的凭据校验、账号状态、后续认证及请求限制共同组成。这里记录用户可观察的行为和管理员操作方式，不承诺所有部署都具有相同的阈值。

## 用户名和邮箱

当前逻辑优先匹配用户名；唯一邮箱可忽略大小写登录。重复邮箱不会随机选一个用户，应使用用户名并由管理员处理资料冲突。

## 账号停用的提示

| 请求情况 | 预期行为 |
| --- | --- |
| 账号不存在或密码错误 | 通用账号/密码错误，不直接暴露账号状态 |
| 凭据正确、账号停用 | 明确提示账号已停用，并拒绝继续登录 |
| 需要双因素验证 | 进入对应验证阶段，不直接签发完整会话 |
| 登录过于频繁 | 限流或拒绝，等待后再试 |

“停用”提示不是通过错误密码就可查询状态的账号探测接口。

## TOTP 与恢复码

在账户中心按向导绑定验证器，确认设备时间同步，完成一次验证码验证后保存恢复码。恢复码应离线安全保存，不与账号密码放在同一个公开位置。

TOTP 是短时动态验证码，恢复码通常是预生成的备用凭据，两者生命周期不同。不能把恢复码视作会自动按分钟过期的 TOTP；使用和撤销规则以对应页面为准。

手机丢失时按实例提供的恢复流程处理，必要时由持有服务器管理权限的管理员执行本地恢复。RelayDock 接入外部 SSO 不代表它自动继承 SSO 的 SMTP 找回密码设置。

## Passkey 与浏览器要求

如果当前版本/实例提供 Passkey，需要规范域名和安全上下文；HTTP IP 直连、域名变更或跨域可能影响凭据使用。先保留可用恢复途径，再尝试新增凭据。

## 防止字典攻击的部署要点

使用唯一强密码、启用支持的二次认证与验证码，保留登录限流，维护真实来源 IP 传递和合理的可信代理边界。观察持续失败和异常地域/时间，而不是通过放宽限制消除错误。

阈值可能随版本和配置变化。排错时不要关闭全站限流来验证一个账号，优先使用测试账号和有限次数的请求。

## 会话和 API 令牌

退出登录、账号停用、密码/令牌轮换属于不同操作，需核对各自生效范围。会话失效后应重新登录，不应把 401 一律展示为“服务器内部错误”。

API 会话凭据放在 Authorization 头，避免 query 参数进入访问日志和复制 URL。浏览器储存位置、记住登录选项和有效期按实例当前实现处理。
