# DDNS：让域名跟随服务器 IP

DDNS 把 Agent 上报的有效公网地址写入 DNS 的 A/AAAA 记录，解决动态 IP 变化后固定域名仍可使用的问题。它不负责 NAT 端口映射，也不负责签发证书。

## 工作顺序

```text
Agent 探测公网地址 → 控制端收到变化 → 选择 DNS 凭据 → 写入 A/AAAA → DNS 缓存逐渐刷新
```

同步目标优先使用服务器的 **节点域名**；为空时回退到服务器管理地址。最终必须是域名，填 IP 无法做 DDNS。

## 配置步骤

1. 在[DNS 服务商管理](/docs/features/dns-providers)保存支持 DDNS 的凭据。
2. 编辑目标服务器，填写节点域名，例如 `origin.example.com`。
3. 启用 DDNS，选择指定服务商，或在具备匹配证书关联时使用自动匹配。
4. 保存并在服务器操作中查看 DDNS 状态/触发重试。
5. 从公共解析器及实际入口网络查询 A/AAAA，确认记录正确。

## 自动匹配如何选择凭据

显式指定 DNS 服务商时使用该记录。自动模式按域名找到匹配证书，再读取证书关联的 DNS 服务商。**只有证书覆盖域名但没有关联凭据，不能自动匹配成功。**

如果只想先使用 DDNS、不需要证书自动匹配，可以显式选择有权限的服务商。

## IPv4 与 IPv6

有效 IPv4 更新 A；有效 IPv6 更新 AAAA。当次没有相应地址时会跳过，而不是自动删除已有记录。因此 IPv6 下线后应检查是否需要人工清理失效 AAAA。

如果 IPv4 与 IPv6 指向不同机器，或节点只监听其中一族，客户端可能出现“有的人能连、有的人不能连”。分别验证两种地址。

## 缓存、重试与传播

当前实现对失败状态有周期重试，约五分钟一轮；也可使用界面提供的手动重试。IP 探测、上报、DNS TTL 和核心缓存都会影响总延迟，不能承诺固定秒数内全网生效。

已有长连接不一定因 DNS 更新立即断开重建。验证时建立新连接并比较解析结果。

## 验证命令

```bash
dig +short A origin.example.com
dig +short AAAA origin.example.com
```

再到 DNS 服务商后台核对记录内容、线路、TTL 和是否有其他 DDNS 客户端同时覆盖。

## 常见失败

| 提示 / 现象 | 检查 |
| --- | --- |
| target is an IP | 节点域名或回退管理地址还是 IP |
| no matching certificate / no DNS provider | 自动匹配缺证书关联，改为显式选择或补关联 |
| unsupported provider | 查[能力表](/docs/features/dns-providers)，证书与 DDNS 支持不同 |
| 认证失败 / 禁止操作 | 凭据格式、权限、域名所属区域 |
| 后台成功、本地仍旧 | TTL、分线路 DNS、缓存和其他客户端覆盖 |
| A 正常、部分客户端失败 | 错误 AAAA、IPv6 路由或监听问题 |
