# 订阅生成、模板与规则

订阅把“用户允许使用的节点”和“客户端需要的格式”组合起来。节点链接正确，不代表完整订阅的规则、分组和输出格式也正确。

## 功能入口对照

| 入口 | 主要用途 |
| --- | --- |
| 节点管理 | 维护连接条目及受管关系 |
| 订阅链接 | 取得面向当前账号的输出链接 |
| 生成订阅 | 按节点、模板和目标客户端生成配置 |
| 订阅管理 | 维护订阅文件及相关记录 |
| 模板管理 | 配置生成结构与分组 |
| 规则配置 / 覆写管理 | 维护规则和局部覆盖 |
| 系统设置 → 订阅 | 同步、缓存、兼容模式及输出行为 |

## 推荐生成顺序

1. 用单节点链接验证节点本身可用。
2. 选择对应客户端格式和模板。
3. 仅加入当前账号被授权的节点。
4. 检查分组引用与规则顺序，保存生成结果。
5. 在测试客户端导入，刷新后验证至少一个实际连接。

不要为了修复模板错误而反复更换节点凭据。

## 完整配置与 Proxy Provider

完整配置通常含代理、分组、规则和 DNS 等部分；Proxy Provider 只输出供其他配置引用的一组节点。系统设置中的 Provider 开关不会把它变成所有客户端通用的完整配置。

使用前确认客户端版本支持所选格式和 Provider 用法。Mihomo/Clash 与 sing-box 的结构不同，不能只把扩展名改成 YAML/JSON。

## 模板和覆写的顺序

覆写可能覆盖模板中已有字段。调整前记录输入、模板版本、所选规则与最终生成结果；先比较最终配置，再判断是哪一层引入了旧地址或错误分组。

外部规则源、订阅源或模板 URL 会被拉取执行解析，应只使用可信来源并检查内容变动。外部节点导入不自动获得本地受管关系。

## 缓存与刷新

后台缓存、CDN、客户端刷新周期可能让新授权/域名暂时未体现。先确认后台生成结果，再检查 HTTP 响应与客户端刷新记录。不要在代理/CDN 层缓存含个人凭据的私有响应。

## 生成失败怎么查

| 现象 | 检查 |
| --- | --- |
| 节点为空 | 账号授权、有效期、筛选、个人凭据部署 |
| 分组引用不存在 | 节点名称变动、模板过滤、规则引用 |
| 只有某客户端报错 | 输出格式、客户端版本、协议能力 |
| 单节点可用、完整配置不可用 | 规则、DNS、分组与覆写 |
| 用户拿到不属于自己的凭据 | 立即停止交付，核对账号及后端生成路径 |

提交反馈时只保留脱敏配置结构，不包含密码、UUID、私钥和订阅令牌。
