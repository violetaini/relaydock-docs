# 证书申请、上传与续期

证书解决 TLS 身份验证。DNS 记录把域名指向地址，两者职责不同：拥有证书不等于解析已正确，解析正确也不代表证书可用。

## 选择方式

| 方式 | 前提 | 适用 |
| --- | --- | --- |
| DNS-01 自动申请 | 可管理该域名的 DNS API 凭据 | 自动化、泛域名证书 |
| 手动上传 | 有证书链与对应私钥 | 外部签发或已有证书 |

DNS-01 通过 `_acme-challenge` TXT 验证，不要求为了这一步在节点开放 80；证书实际使用的业务端口仍需开放。

## DNS-01 流程

1. 先保存[支持的 DNS 凭据](/docs/features/dns-providers)。
2. 在证书管理新建申请，选择服务商和域名。
3. 需要根域与泛域时分别包含 `example.com` 与 `*.example.com`。
4. 提交后查看状态与错误，等待 DNS 挑战完成。
5. 检查签发域名、到期时间和关联服务商，再分配给需要的服务器/入站。

泛域名 `*.example.com` 一般不覆盖根域 `example.com`，也不覆盖更深的 `a.b.example.com`。不要只看“有泛域证书”就认为所有主机名都匹配。

## 手动上传

上传完整证书链和匹配私钥，检查 PEM 格式、域名覆盖和有效期。私钥不应出现在公开仓库、截图或错误反馈里。

手动证书不会凭空获得自动续签能力。若后台允许关联 DNS 服务商，应明确该关联用于什么流程；只有具备完整申请/续期配置才可依赖自动化。

## 部署到服务后验证

证书记录保存成功不等于所有服务已加载新证书。还需核对远端部署结果、文件权限及核心/Nginx 是否重载。

```bash
openssl s_client -connect node.example.com:443 -servername node.example.com </dev/null
```

检查实际呈现的证书，而不只看面板证书列表。对非 443 入站替换端口。

## 续期维护

定期查看到期时间及最近错误，确保 DNS 凭据仍有效、控制端时间准确、能访问 ACME 服务。续期失败不要连续重复申请触发 CA 频率限制；按错误处理 TXT 权限、解析传播或域名配置。

## 常见错误

- **域名不匹配**：SNI 与证书 SAN 不一致，或误认为泛域覆盖根域/多级域。
- **证书链不完整**：仅上传叶子证书，客户端缺中间链。
- **私钥不匹配**：证书与另一份密钥混用。
- **面板已更新、客户端仍旧**：服务未重载、CDN 呈现的是另一张边缘证书，或连到了错误 IP。
- **自动 DDNS 找不到凭据**：证书没有关联 DNS 服务商，见[DDNS](/docs/features/ddns)。
