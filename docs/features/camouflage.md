# 前置、伪装站与 WSS

前置配置用于让网站服务、TLS 和代理业务按预期协作。它会涉及监听地址、端口、证书和 Nginx，不应在已有生产站点上直接套用整段配置。

## 先画出真实拓扑

```text
外部客户端 → 443 的 TLS/网站入口 → 本机或远端的业务监听
普通网页请求 → 静态站点或反向代理站点
```

具体 Tunnel/Fallback 行为按所选模板和当前界面决定。不要同时让 Nginx 与核心直接监听同一地址的同一 TCP 端口。

## 前置配置检查表

| 项目 | 需要确认 |
| --- | --- |
| 域名与证书 | 域名解析和证书覆盖正确 |
| 443 归属 | 入口由谁监听，是否有重复服务 |
| 内部端口 | 绑定本机还是对外，和前置目标一致 |
| Host / SNI / path | 与入站传输组合及客户端一致 |
| Nginx 管理模式 | 托管还是复用现有环境 |
| 站点目标 | 静态路径存在，或代理 URL 可从服务器访问 |

## 伪装站目标

使用自己有权代理、稳定可达的目标。反代到第三方网站可能受到证书、Host、跳转、内容安全策略和对方访问限制影响，不保证任意 URL 都能使用。

当前界面对某些 Cloudflare 目标有风险检查。应保留检查结果并选择合适目标，不能通过更换写法绕开后端校验。此检查不代表能识别所有 CDN、消除所有网络风险。

## WSS 与 CDN 的边界

WSS 是使用 TLS 的 WebSocket。即便 CDN 支持 WebSocket，也需核对其可代理端口、空闲超时、请求大小和规则限制。

普通 Shadowsocks TCP、UDP、WireGuard 等不能因为域名开启橙云就自动穿过网站 CDN。Cloudflare DNS-only 记录与橙云代理记录应分清。

## 配置顺序

1. 备份原 Nginx/核心配置，记录端口归属。
2. 准备域名和证书，验证服务器对目标站点可达。
3. 选择托管/复用模式和前置方式。
4. 核对内外端口与转发目标，保存等待远端结果。
5. 分别测试普通浏览器访问和真实代理连接。

网页能打开只说明网站路径可用；代理仍需对应客户端验证。

## 故障时如何回退

出现配置拒绝或端口冲突，保留首个报错并恢复已备份的受影响配置。不要结束不认识的进程，也不要恢复整台机器的旧数据库来解决一份 Nginx 配置问题。

更多连接层排错见[排错手册](/docs/operations/troubleshooting)。
