## 2. 实体依赖与配置关系图 (ER Diagram)

平台内部各个核心配置实体的层级与从属关系如下：

```text
[ 用户 / 管理员 (Users) ]
        | 1:N 拥有与授权
        v
[ 远程服务器 (Remote Server) ] 
  ├── 关联模式: WebSocket / Push / Pull
  ├── 核心引擎: 全托管内嵌核心 (Embedded) / 外部接管模式 (External)
  ├── Nginx 模式: Arcway 管理托管 / 复用系统已有
  ├── 计量口径: VPS 物理网卡口径 / Xray 节点聚合口径
  │
  ├── 关联 -> [ 节点域名与 DDNS (Domain & DDNS) ]
  │                 |
  │                 v (自动匹配推导)
  │           [ 泛域名证书 (Certificates) ]
  │                 |
  │                 v (复用凭据)
  │           [ DNS 提供商 (DNS Providers: 华为云/CF/DNSPod) ]
  │
  └── 承载 -> [ 代理入站节点 (Inbounds / Proxies) ]
                    ├── 协议: VLESS / VMess / Trojan / Shadowsocks / Hysteria2
                    ├── 传输: TCP / WebSocket / gRPC / HTTP/2
                    └── 安全: TLS 证书加固 / REALITY 伪装
```

## 3. 动态 DDNS 与证书推导时序图

当节点服务器为**动态公网 IP**（如家用宽带、动态 IP VPS）时，系统全自动完成解析更新的全流程时序：

```text
[节点 Agent]             [控制端 RelayDock]        [泛域名证书库]      [DNS 服务商 API]
     |                         |                       |                   |
     |--- 1. 上报当前最新 IP --->|                       |                   |
     |    (例如 170.9.59.149)   |                       |                   |
     |                         |--- 2. 检测到 IP 变动 --|                   |
     |                         |    目标: jp.chitanda.net                  |
     |                         |                       |                   |
     |                         |--- 3. 匹配根证书 ----->|                   |
     |                         |    (匹配 *.chitanda.net)                  |
     |                         |<-- 返回关联提供商: 华为云 |                   |
     |                         |                       |                   |
     |                         |--- 4. 调用 API 更新 A/AAAA 记录 --------->|
     |                         |    (Host: jp, IP: 170.9.59.149)           |
     |                         |<-- 5. 解析同步成功 (生效时间 1~60s) --------|
     |                         |                                           |
     |<-- 6. 下发最新状态 ------|                                           |
     |    (DDNS 状态标绿)       |                                           |
```

## 4. 八大核心功能模块深度复盘对照表

| 模块代码 | 模块名称 | 解决的核心痛点 | 交互与底层技术实现 |
| :--- | :--- | :--- | :--- |
| **M1** | **极简服务器接入** | 传统面板每个节点手动安装配置极其繁琐 | 提供安全单向 Token 接入命令；支持 WebSocket 长连接保活、Push 推送与 Pull 轮询 |
| **M2** | **全托管 Xray 核心** | 外部 Xray 进程容易被杀、产生僵尸进程或版本冲突 | 底层直接将 `xray-core` 作为 Go 包编译进 Agent，单进程零残留；随 Agent 升级自动平滑升级 |
| **M3** | **智能动态 DDNS** | 传统 DDNS 下拉菜单证书过多导致列表无限膨胀 | 精简下拉为「自动匹配」与「具体服务商」；输入框引入根域名快捷 Chips 与带即时搜索的浮层 |
| **M4** | **证书生命周期** | 泛域名申请繁琐、手动证书无法复用 DNS 凭据 | 支持 Let's Encrypt DNS-01 自动签发与静默续签；手动上传 PEM/KEY 允许绑定 DNS 提供商以复用 |
| **M5** | **443 伪装与防穿透** | 反代套了 CF CDN 的网站导致 VPS 被当成优选节点扫射 | 提供 Tunnel / Fallback 接管；保存反代伪装站点前自动进行 Cloudflare CDN 撞墙检测与拦截 |
| **M6** | **多源精准流量计量** | VPS 服务商账单与代理节点统计数据严重不一致 | 支持「VPS 物理网卡」与「Xray 节点聚合」双口径，提供每月重置日与单向/双向统计规则 |
| **M7** | **原生网络测速** | 无法直观评估远程各节点 VPS 到官方测速点的网络质量 | 节点内嵌 Ookla Speedtest 原生引擎，实时测算上传/下载带宽、时延、抖动与服务器信息 |
| **M8** | **安全与权限审计** | 账号被停用时含糊提示“密码错误”，缺少双因素认证 | 账号停用明确拦截；支持 Google Authenticator TOTP 2FA 双因素安全登录与审计日志 |
