# 系统架构与数据流

理解控制流、代理业务流和订阅生成流，可以快速判断故障发生在哪一层。

[![控制通道与业务通道的区别](/images/architecture.svg)](/images/architecture.svg)

## 控制端负责什么

控制端提供网页、HTTP API、账号与授权管理、节点数据、订阅生成，以及对远端服务器的操作编排。默认使用 SQLite 存储运行数据；数据库路径可随安装方式不同。

前端既可以内嵌在控制端二进制，也可以由受管外置目录提供。只更新其中一部分可能造成网页字段、API 或静态资源不匹配。正式产品更新会校验配套关系，见[更新](/docs/operations/update)。

## Agent 与核心负责什么

Agent 运行在节点服务器上，提供资源和公网地址上报、配置执行、核心管理等能力。WebSocket 模式由 Agent 主动连接控制端；Push/Pull 的方向不同，见[模式对比](/docs/servers/connection-modes)。

Xray 核心可以内嵌在 Agent 进程，也可以采用外部模式。内嵌模式下没有独立 `xray.service` 并不代表核心没运行，应检查端口及 Agent 状态。

## 客户端流量经过哪里

直连节点时，客户端连接节点服务器的业务端口。控制端通常不在这条数据路径上，因此不能根据“面板网页正常”推断代理业务正常。

任意门转发时：

```text
客户端 → 入口服务器 A:入口端口 → 目标服务器 B:目标端口 → 目标网络
```

A 接收并转发 TCP/UDP，B 仍按原协议处理。转发不是更换客户端协议，也不是自动建立 VPN。入口和出口之间必须真实可达。

## 配置保存与远端生效

网页操作一般经过以下阶段：

1. 校验用户身份、授权范围及输入；
2. 控制端记录或构建配置意图；
3. 通过 Agent 执行；
4. 根据远端结果更新状态或报错。

涉及任意门绑定等操作时，需要等待远端确认。请求已发出、界面显示了新值，并不足以证明核心已接受配置。超时或状态不确定时先刷新并检查日志，不要连续重复提交。

## 订阅和计量的关系

订阅生成根据当前用户的可用服务、节点选择和个人凭据输出客户端配置。管理员导出的链接不能直接当作普通用户链接交付。

流量有服务器网卡统计、节点业务统计和用户计费等层次。它们服务于不同目的，不能将服务器整机总流量直接当作某一用户的用量，详见[流量口径](/docs/features/traffic)。

## 控制端短暂不可用时

已经运行的核心不一定立即停止转发，但新配置、订阅刷新、实时状态与部分限制同步会受影响。到期守卫等本地组件是否就绪也会影响行为，不能把“断开主控”当作绕过限制的方法。维护前应检查关键组件及恢复方案。
