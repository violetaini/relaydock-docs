## 核心通信模式详解

在「添加服务器」或「编辑服务器」时，您可以针对不同服务器的网络环境选择最合适的连接模式：

### 1. WebSocket 模式（默认推荐）
- **机制**：Agent 启动后，主动向控制端发起安全的 WebSocket (WSS) 长连接，心跳实时保持。
- **适用场景**：绝大多数公网 VPS、NAT 小鸡、动态 IP 宽带服务器。
- **优点**：即使节点没有独立公网 IP 或处于内网穿透环境，只要能访问控制端即可秒级上线。

### 2. HTTP Push 模式
- **机制**：Agent 定期将自身状态、流量、心跳通过 HTTP POST 请求推送给控制端。
- **适用场景**：长连接易被中间防火墙重置、或严格限制长连接保活的环境。

### 3. HTTP Pull 模式
- **机制**：控制端定期主动连接 Agent 监听的端口抓取指标与下发配置。
- **适用场景**：节点拥有极佳的固定公网 IP，且控制端需严格控制抓取时机的环境。
