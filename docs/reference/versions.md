## 提交、构建与 Release 的区别

| 动作 | 表示什么 |
| --- | --- |
| 推送源码提交 | 仓库内容更新 |
| CI 通过 | 当前构建/检查通过，不自动说明已部署 |
| 创建完整正式 Release | 安装器与更新系统可获得对应资产 |
| 部署到实例 | 该实例实际使用新程序/网页 |

因此“仓库里已经有新代码”与“面板检查到可升级版本”可以同时不成立。不要为取得某项修复随意覆盖一半组件。

## 如何核对自己的实例

查看系统更新页、Agent 版本、核心模式和网页元数据。正式产品部署若提供 `/relaydock-release.json`，可将其与当前发布状态比对；手工构建未必包含该文件。

检查前后端是否一致，外置网页是否仍指向旧目录，以及浏览器/CDN 是否缓存旧 HTML。相关更新边界见[更新手册](/docs/operations/update)。
